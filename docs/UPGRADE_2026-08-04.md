# Upgrade Rehberi — 2026-08-04 Düzeltme Paketi

## 1. Yedek

PostgreSQL veritabanını ve mevcut `.env` dosyasını yedekleyin. Migration'lar additive olsa da shared report duplicate satırlarını tek lifecycle satırına indirger.

## 2. Ortam değişkenleri

Production için aşağıdakiler zorunludur:

```env
ENVIRONMENT=production
SECRET_KEY=<uzun-rastgele-değer>
ADMIN_PASSWORD_HASH=<bcrypt-hash>
ENCRYPTION_KEY=<Fernet-key>
DB_PASSWORD=<uzun-rastgele-parola>
```

`docker-compose.yml` PostgreSQL ve backend için aynı `DB_PASSWORD` kaynağını kullanır.

## 3. Python ve bağımlılıklar

Python 3.11–3.13 kullanın:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip wheel
pip install -r backend/requirements.txt
```

## 4. Migration

```bash
alembic -c backend/alembic.ini upgrade head
```

Beklenen head:

```text
f708192a3b4c
```

Yeni migration'lar:

1. `d5e6f708192a` — cache temporal provenance
2. `e6f708192a3b` — assistant action confirmations
3. `f708192a3b4c` — shared report revoke/rotate lifecycle

SQLite development kurulumlarında uygulama açılışındaki idempotent normalizer aynı additive alan ve indeksleri tamamlar.

## 5. Frontend

```bash
cd frontend
npm ci
npm run lint
npm test
npm run build
```

Kullanıcıların ilk açılışta yeniden giriş yapması önerilir. Eski `localStorage` access/refresh ve analiz state kayıtları istemci tarafından temizlenir veya `sessionStorage` alanına taşınır.

## 6. Historical analiz davranış değişikliği

Geçmiş tarihte live-only araçlar artık kapalıdır. Bazı analist kartlarında “data unavailable” görülmesi bir regresyon değil, point-in-time veri sızıntısını engelleyen fail-closed davranıştır. Bu raporlar için gerçek geçmiş snapshot gerekiyorsa arşiv sağlayıcı eklenmelidir.

## 7. Assistant işlemleri

Assistant order/alert komutları artık doğrudan yürütülmez. Kullanıcı önizlemedeki 32 karakter confirmation ID'yi sonraki mesajında açıkça onaylamalıdır. Onay 10 dakika geçerlidir ve yalnız bir kez kullanılabilir.

## 8. Dağıtım

`deploy/update.sh` kullanılıyorsa `/etc/tradingagents/update.env` içinde `PROJECT_ROOT`, `SERVICE_NAME`, `RUN_USER` ve `VENV` değerlerini doğrulayın. Script migration downgrade yapmaz; yeni migration'lar önceki uygulama sürümüyle expand/contract uyumlu tutulmalıdır.
